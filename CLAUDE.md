## Build & Run

No Maven wrapper is checked in. Use system `mvn` directly.

```bash
# Build (skip tests)
mvn clean package -DskipTests

# Run locally (requires PostgreSQL running)
mvn spring-boot:run

# Run with Docker Compose (PostgreSQL + app + nginx)
docker-compose up --build

# Run a single test class
mvn test -Dtest=ClassName

# Run all tests
mvn test
```

**Running tests inside Docker** (no local JDK/Maven required):
```bash
docker run --rm -v "$(pwd):/app" -w /app maven:3.9-eclipse-temurin-21-alpine mvn test --batch-mode "-Dsurefire.useFile=false"
```
On Windows PowerShell the `-D` flag must be quoted or passed as a separate argument — passing it unquoted causes the build system to treat `.useFile=false` as a lifecycle phase and fail.

Environment variables (see `.env.example`): `DB_NAME`, `DB_USER`, `DB_PASSWORD`, `JWT_SECRET` (64+ chars), `JWT_EXPIRATION_MS`, `SERVER_PORT`.

**Docker DB credentials** (default compose stack): `DB_USER=hhm`, `DB_NAME=estate_erp`, `DB_PASSWORD=2003`. Container name: `estate_erp_db`.

## Architecture

Single Spring Boot 3.2.3 / Java 21 monolith, intentionally sized for ~10 users (no microservices). Structured as:

```
controller → service → repository (Spring Data JPA) → PostgreSQL 16
                ↕
             mapper (entity ↔ DTO)
```

**Layers:**
- `controller/` — REST controllers, all under `/api/v1/`. One controller per domain entity.
- `service/` — Business logic in coarse-grained services: `AuthService`, `DailyOperationsService`, `DashboardService`, `FinanceService`, `WorkforceService`. Each service may span multiple repositories.
- `dto/` — Request/response objects in sub-packages by domain (e.g., `dto/latex/`, `dto/employee/`). Never expose entities directly.
- `mapper/` — Static utility classes (no MapStruct annotation processor). Each mapper has a private constructor and only `public static` methods: `toEntity(...)`, `toResponse(...)`, `toSummaryResponse(...)`.
- `entity/` — JPA entities. `BaseEntity` provides `createdAt`, `updatedAt` via `@PrePersist`/`@PreUpdate`. All primary keys are `UUID.randomUUID().toString()` set in the mapper, not generated by the DB.
- `security/` — JWT stateless auth. `JwtAuthenticationFilter` builds `Authentication` from JWT claims only (no DB hit per request). `CustomUserDetailsService` is only used during login. BCrypt strength 12.
- `exception/` — `GlobalExceptionHandler` (`@RestControllerAdvice`) handles domain exceptions and returns a uniform `ApiError`. **Important:** `AccessDeniedException` and `AuthenticationException` are explicitly re-thrown from the generic handler so Spring Security's `ExceptionTranslationFilter` can correctly distinguish anonymous callers (→ 401) from authenticated callers lacking a role (→ 403). Do not add an `@ExceptionHandler(AccessDeniedException.class)` here.

**Database:**
- Flyway manages schema: migrations in `src/main/resources/db/migration/`. Current state: V1 = full schema, V2 = seed data, V3 = schema updates (new tables + column changes), V4 = `is_working` column on `calendar`.
- Hibernate runs in `validate` mode — every entity field change requires a new Flyway migration file. Add changes to the entity AND write a `V{n+1}__description.sql` file before starting the app.

**Security:**
- Public endpoints: `/api/v1/auth/**`, `/swagger-ui/**`, `/v3/api-docs/**`, `/api-docs/**`
- All other routes require a valid JWT Bearer token.
- Roles stored with `ROLE_` prefix (`ROLE_ADMIN`, `ROLE_SUPERVISOR`). `hasRole('ADMIN')` auto-prepends the prefix; `hasAnyRole('ADMIN','SUPERVISOR')` is the common pattern for read endpoints.
- Method-level security enabled via `@EnableMethodSecurity` in `SecurityConfig`.

**Key domain behaviour:**
- `DailyOperationsService.createOrUpdateCalendar` is an upsert keyed on `calendar_date`. When a day is marked as non-working (`isWorking=false`), a holiday, or rained-on, it auto-generates default no-work attendance records for every active employee who has not already been logged for that day.
- `DailyOperationsService.createAttendanceBulk` is fully atomic — all records share a single `@Transactional` boundary. It calls a private `createAttendanceInternal` helper instead of the public `createAttendance` to avoid Spring's proxy-bypass problem (calling `this.@Transactional` method directly skips the AOP proxy).

**API Docs:** Swagger UI available at `/swagger-ui.html` when running.

**Reports:** Apache POI (`poi-ooxml`) is used for Excel export functionality.

**Infrastructure:** Docker Compose runs three services — `db` (PostgreSQL 16, container `estate_erp_db`), `app` (port 8080, container `estate_erp_app`), `nginx` (ports 80/443). Nginx proxies `/api/*`, `/swagger-ui/*`, `/api-docs/*` to the app; all other paths return 404.

## Testing

Tests live in `src/test/java/...` mirroring the main package structure. All existing tests use `@WebMvcTest` (no DB required).

### `@WebMvcTest` patterns for this codebase

`@WebMvcTest` does not auto-scan `@Component` beans outside the web layer (`JwtAuthenticationEntryPoint`, `JwtAccessDeniedHandler`). Without them `SecurityConfig` can't be constructed, so neither CSRF rules nor `@EnableMethodSecurity` are applied. Always include the following on every controller test class:

```java
@WebMvcTest(MyController.class)
@Import({JwtAuthenticationEntryPoint.class, JwtAccessDeniedHandler.class})
class MyControllerTest {

    @TestConfiguration
    @EnableMethodSecurity
    static class MethodSecurityConfig {}

    @MockBean private MyService myService;
    @MockBean private JwtTokenProvider jwtTokenProvider;
    @MockBean private CustomUserDetailsService customUserDetailsService;
}
```

**If the controller has public (`permitAll()`) endpoints** (e.g. `AuthController`), also import `SecurityConfig` so the URL-level permit rules are applied:

```java
@Import({JwtAuthenticationEntryPoint.class, JwtAccessDeniedHandler.class, SecurityConfig.class})
```
When `SecurityConfig` is imported the `@TestConfiguration @EnableMethodSecurity` inner class is redundant (SecurityConfig already declares it) but harmless.

**CSRF:** Spring Security test enforces CSRF for POST/PUT/DELETE regardless of the app config. Add `.with(csrf())` to every mutating request:

```java
mockMvc.perform(post("/api/v1/...").with(csrf()).contentType(...).content(...))
```

**Custom principal:** Endpoints using `@AuthenticationPrincipal UserPrincipal` won't work with `@WithMockUser` (wrong principal type). Use the `user()` post-processor instead:

```java
UserPrincipal principal = new UserPrincipal("id", "username", "email", "pw",
        List.of(new SimpleGrantedAuthority("ROLE_ADMIN")));

mockMvc.perform(get("/api/v1/auth/me").with(user(principal)))
```

**Unauthenticated 401 vs 403:** Unauthenticated requests to `permitAll()` endpoints that have `@PreAuthorize` will get 403 (from Spring MVC's `@ControllerAdvice`) instead of 401 **unless** `AccessDeniedException` is re-thrown to the security filter chain. The `GlobalExceptionHandler` already handles this correctly — don't break it.
